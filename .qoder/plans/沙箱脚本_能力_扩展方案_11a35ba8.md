# 沙箱脚本能力扩展方案

## 一、功能定位与范围

根据本次确认，新增类型命名为“沙箱”，内部标识为 `kind: 'sandbox'`，与“行动”“注入”并列。

| 类型 | 运行环境 | 典型用途 | 生命周期 |
| --- | --- | --- | --- |
| 行动 | 绑定网站和标签 | 页面操作、采集 | 执行完成或超时结束 |
| 注入 | 随绑定网站运行 | 请求改写、页面初始化 | 随网站运行 |
| 沙箱 | 独立 Node.js 子进程 | 数据计算、接口请求、HTTP 服务 | 一次性或常驻 |

本期包含：创建、编辑、变量配置、运行、停止、运行日志、数据输出、导入导出，以及对应 MCP 能力。

本期不包含：npm 安装与依赖管理、系统 Node.js 下载、任务编排接入、步骤间数据传递、开机自启、应用退出后的后台托管、自动重启、容器或操作系统级安全隔离。

## 二、用户操作与运行规则

### 编辑与运行
- 类型选择和分类筛选增加“沙箱”；列表显示运行模式与状态。
- 沙箱不填写适用域名，运行时不选择网站或标签；即使没有创建网站也能执行。
- 增加“运行模式”：`once`（一次性，默认）或 `service`（常驻）。
- 复用现有变量声明：文本、数字、开关、枚举，支持默认值、必填及数值范围；脚本通过 `octo.vars` 读取。首版不新增 JSON 变量控件，复杂输入可以文本传入后解析。
- 运行表单沿用“默认值 → 上次参数 → 本次修改”的交互；最终参数通过共享校验后保存，供下次使用。MCP 未传的参数使用声明默认值，不隐式读取上次运行参数。
- 点击运行或启动后打开日志；列表和日志内均可停止。关闭日志窗口不停止脚本。
- 同一个沙箱脚本同时只运行一个实例；不同沙箱可并行，首版全局最多 4 个沙箱实例，不占用行动的网站运行名额。
- 运行中禁止编辑、删除及清空日志；修改配置后需要停止再启动。

### 两种模式
| 项目 | 一次性 | 常驻 |
| --- | --- | --- |
| 源码执行 | 执行一次异步函数体 | 执行一次异步初始化函数体 |
| 源码返回 | 保存最终结果并结束 | 保存初始输出，进入“运行中”，继续保留服务、定时器及回调 |
| 超时配置 | 整次执行超时 | 仅限制初始化 |
| 时间范围 | 1–600 秒，默认 60 秒 | 初始化 1–600 秒，默认 60 秒；就绪后不设运行时限 |
| 结束方式 | 完成、失败、超时、手动停止 | 手动停止、运行异常、应用退出 |

常驻脚本必须等待服务真正监听成功后再返回，返回即表示初始化完成。初始化中永久等待会触发初始化超时。常驻模式即使没有活动句柄，也由宿主保持运行，不根据事件循环是否空闲自动结束。

应用退出时提示存在运行中的沙箱，并停止全部实例；重启应用不自动恢复执行。异常退出留下的运行记录恢复为“异常中断”。

## 三、JavaScript 编写契约

### 环境与模块
- 使用随 Electron 附带的 Node.js，不依赖用户安装系统 Node.js；契约中展示实际 Node.js 版本。
- 开放该版本和操作系统提供的全部 Node.js 内置模块，包括 `node:http`、`node:https`、`node:fs`、`node:path`、`node:crypto`、`node:net`、`node:child_process`、`node:worker_threads` 等。
- 支持 `require('node:http')`、`require('http')` 和 `await import('node:http')`；对于只能以 ESM 加载的内置模块使用动态导入。
- 提供 Node.js 全局能力，如 `process`、`Buffer`、`fetch`、定时器等。模块行为仍遵循内置 Node.js 版本、操作系统权限和进程上下文；外部命令不随应用附带。
- 源码延续现有“异步函数体”格式，可直接 `await`、`return`，不使用静态 `import/export` 或 `module.exports`。
- 不提供第三方包安装或依赖解析契约，不把应用自身的 npm 依赖、Electron API 暴露为受支持的脚本接口。模块入口检查用于明确产品支持范围，不宣称能阻止可信代码绕过。
- 不注入 `page`、`browser`、`octo.site` 或浏览器登录态。

### `octo` API
- `octo.vars`：本次运行校验后的参数快照。
- `octo.log(...)`、`console.log/info/warn/error/debug(...)`：写入运行日志。
- `octo.sleep(ms)`：异步等待。
- `octo.output(value)`：设置当前输出。
- `octo.onDispose(callback)`：注册资源清理函数，支持异步；收尾时逆序调用且只调用一次。
- 复用已有 `octo.notify(...)`，仅补充“沙箱”来源标识，保持现有通知语义。

每个脚本使用稳定工作目录 `<用户数据目录>/sandbox-data/<scriptId>/`，`process.cwd()` 指向该目录，方便使用相对路径。该目录不是文件访问隔离边界。导出不包含工作目录文件，删除脚本不自动删除其产出的文件。

### 数据产出
- 支持 JSON 值：对象、数组、字符串、数字、布尔值、`null`；沿用 64K 字符上限，不允许循环引用、BigInt、函数等无法按契约序列化的结果。
- 一次性模式：`octo.output` 暂存结果；非 `undefined` 的 `return` 覆盖暂存值；仅成功完成时保存最终结果，失败、超时或取消不保留暂存结果。
- 常驻模式：`return` 设置初始化输出；运行中的回调可继续调用 `octo.output` 更新“最新输出”。只保留最后一份快照，不累计无限结果列表。
- 常驻结束后保留最后有效快照，界面标明“最新输出（非最终成功结果）”；状态和错误独立显示，避免把失败服务的历史快照当成成功。
- 无输出时不伪造结果；非法输出报错，未捕获时结束运行。

### 示例：参数化 HTTP 服务

选择“沙箱 / 常驻”，声明 `host`（文本，默认 `127.0.0.1`）、`port`（数字，默认 `3000`，范围 1–65535）、`message`（文本）。

```js
const http = require('node:http');
const { once } = require('node:events');

const server = http.createServer((req, res) => {
  console.log(req.method, req.url);
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ message: octo.vars.message }));
});

octo.onDispose(() => new Promise((resolve) => server.close(resolve)));
server.listen(octo.vars.port, octo.vars.host);
await once(server, 'listening');

console.log('HTTP 服务已启动', server.address());
return { host: octo.vars.host, port: server.address().port };
```

模板默认仅监听本机。用户主动改成 `0.0.0.0` 等地址会扩大网络可访问范围，契约和示例提示需自行处理鉴权；端口被占用时直接失败并显示 `EADDRINUSE`，不静默更换端口。

## 四、实现结构与生命周期

### 独立运行进程
现有行动执行器需要连接 Puppeteer，并采用 Worker：[runner.ts](file:///Users/fanhaozhi/Desktop/octo-fetch/src/main/scripts/runner.ts)、[worker.ts](file:///Users/fanhaozhi/Desktop/octo-fetch/src/main/scripts/worker.ts)。沙箱新增专用执行路径，不改动行动及注入的执行机制。

- 新增 `src/main/scripts/sandbox.ts`：负责实例管理、并发限制、状态、超时、日志和输出检查点。
- 新增 `src/main/scripts/sandbox-process.ts`：通过 Electron `utilityProcess.fork` 启动，执行 Node.js 脚本并与主进程通信。
- 在现有 `ScriptRunner` 中按已保存的脚本类型分派；统一聚合 `active/runs/cancel/shutdown`，继续复用 `ScriptStore`、`ScriptLogStore` 和现有 IPC/MCP 入口。
- 执行前持久化初始记录；通信消息校验运行身份、类型与尺寸。异步结果、停止、崩溃等竞态只允许一次收尾。
- 未捕获异常、未处理 Promise 拒绝、非预期进程退出均记为失败；不能仅凭 `process.exit(0)` 判定脚本成功。
- 一次性完成、失败、超时、取消和应用退出均进入统一清理流程。先请求清理，最多等待 3 秒；随后终止进程。若普通终止未退出，再由主进程对仍归属于该实例的 PID 强制结束，并等待退出确认后释放运行名额。
- 常驻停止期间显示“停止中”；正常手动停止复用 `cancelled` 终态，在沙箱界面显示“已停止”，通过结束原因区分用户停止、应用退出和异常。
- 脚本创建的服务器和线程随托管进程结束释放；自行启动的外部子进程应通过 `octo.onDispose` 清理。首版不承诺自动回收任意后代进程或主动脱离托管的后台进程。

### 共享模型与兼容
主要调整 [scripts.ts](file:///Users/fanhaozhi/Desktop/octo-fetch/src/shared/scripts.ts)：
- 新增 `sandbox` 类型，沙箱专属配置为 `sandbox: { mode: 'once' | 'service' }`；新建默认一次性，非沙箱禁止携带该配置。
- 沙箱的 `match` 规范化为 `[]`；行动和注入仍必须声明适用域名。
- 运行请求中的网站字段允许缺省，由执行器依据已保存的类型校验：行动必须提供网站；沙箱禁止携带网站或标签字段；注入仍禁止直接运行。
- 运行记录保存类型、模式和生命周期阶段；沙箱不写虚假的网站 ID。浏览器类运行记录仍强制要求其网站字段。
- 活跃运行摘要增加类型、模式和阶段，避免网站锁、运行统计把沙箱误算为行动。
- 原脚本缺省类型仍为 `action`，旧运行记录继续可读；沙箱导出使用元数据版本 3，行动/注入保持现有版本 2 导出，新导入器兼容版本 1/2/3。
- 类型转换清理不适用配置但不覆盖用户源码；已绑定注入及任务引用规则保持现有校验，任务编排仍只接受行动。

### 界面、集成与打包
- 调整现有 `Scripts.tsx`、`ScriptEditor.tsx`、`ScriptRun.tsx`，不另建独立页面；提供“一次性计算”和“HTTP 常驻服务”模板。
- 调整 `CodeEditor.tsx` 的运行环境提示，沙箱显示 Node.js 与 `octo` 接口，不提示其不存在的浏览器对象；切换模板仅替换未修改的默认模板。

- MCP 沿用 `save_script/run_script/cancel_script_run/read_script_runs`；沙箱运行不传 `site_id`。常驻返回受理后，Agent 轮询至“运行中/初始化失败”，不等待它自然结束，也不把受理等同于服务就绪。
- `list_scripts(kind='sandbox')` 支持筛选；按 URL 查询时沙箱视为与网站无关的通用能力，不因没有域名而遗漏。

- 在 `electron.vite.config.ts` 添加沙箱进程构建入口；验证 ASAR 打包后可启动，工作目录位于可写用户数据目录，不依赖项目 `node_modules` 路径。

## 五、运行日志与持久化

现有日志 UI 与持久化可复用，但当前行动 Worker 达到累计日志限额后不再发送后续日志，不适合直接用于常驻服务。

- 沿用每个脚本最近 20 次运行、每次最近 300 条日志、单条最多 2000 字符。
- 沙箱采用持续滚动日志；运行很久后仍能看到最新请求，不因前 300 条已满而永久停止记录。
- 结构化日志在子进程限流、限量批发，首版最多 100 条/秒；超限记录省略数量，异常与结束信息单独保障。
- 捕获 stdout/stderr 作为补充，持续消费并限制缓冲区大小，兼容没有换行的输出，避免输出洪水阻塞主进程；结构化 console 日志不重复记入。
- 日志和最新输出约每 500ms 合并落盘，结束时立即保存；常驻高频输出合并为最新快照，避免无限消息队列。
- 日志 UI 延用自动刷新、等级筛选、错误堆栈和结果复制；沙箱显示“独立 Node.js”，不展示网站占位字段。
- 磁盘写入失败沿用现有内存兜底及告警，明确数据尚未持久化。

## 六、安全与能力边界

“沙箱”是产品类型名称，不表示安全沙箱。独立进程用于隔离执行生命周期，不能阻止脚本访问本机文件、网络或进程，也不能保证恶意代码不影响宿主。

编辑及运行界面明确提示：仅运行可信代码；停止无法撤销已发生的文件修改、网络请求或外部进程行为；源码、变量、日志和输出明文保存在本机。界面与 MCP 不自动传入应用凭据或浏览器会话。

## 七、验收与测试

### 功能验收
1. 不创建、不启动任何网站，仍可新建沙箱，配置数字参数并返回计算结果，关闭再打开应用后可读取记录。
2. HTTP 常驻服务正确读取 host/port/message；初始化完成后保持运行，客户端请求获得配置的响应，日志持续更新。
3. 停止服务后端口释放，同一脚本可再次启动；有长连接时清理有界，不永久卡在停止中。
4. 端口冲突、语法错误、未捕获异步异常、进程退出均显示明确失败原因。
5. 一次性死循环、初始化死循环可被超时终止；常驻进入运行后发生死循环仍可手动停止，客户端保持可操作。
6. 超过 300 条日志后保留最新日志，高频 stdout 和结果更新不造成无界缓存；结束状态与错误信息可见。
7. 正常退出应用停止全部沙箱；强制结束应用的测试验证托管进程退出及端口释放，重启后残留记录标记异常中断，不自动续跑。
8. 验证 `http/fs/path/crypto/child_process/worker_threads` 等代表模块以及动态导入；不依赖额外 npm 安装。文件读写只在测试数据目录，外部进程测试使用短生命周期受控进程。
9. MCP 全链路覆盖保存、无网站运行、常驻就绪、输出读取、停止及权限校验。
10. 旧行动、注入、任务编排、通知及版本 1/2 导入回归通过，沙箱版本 3 导入导出往返无数据损失。
