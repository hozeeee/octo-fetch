# Octo Fetch 基础工作台

## 已确认范围
- 平台为 macOS，随应用附带匹配版本的 Chrome for Testing；运行时不要求用户安装 Chrome 或下载浏览器。
- 主界面同时展示 1～4 条网站配置的画面；点击卡片进入放大操作视图，返回后继续网格总览。
- 每条配置拥有独立登录态；同一网站可以配置多个互不影响的账号。
- 每条配置内部支持多标签，包括网站弹窗、第三方登录产生的新页面。
- 支持基础鼠标键盘交互、中文输入、文本复制粘贴、前进、后退、刷新。
- Cookie 同时支持 JSON、`name=value; name2=value2` 字符串和逐项表格编辑。
- 首期不包含采集脚本、任务调度、采集结果存储、文件上传下载、音视频、扩展插件、代理池、自动更新或风控绕过。

## 技术架构与工程组织
- 使用 npm、electron-vite、Electron、React、TypeScript、Ant Design、Zustand、Zod；运行环境满足 Puppeteer 的 Node.js 要求，依赖以 lockfile 锁定。
- Puppeteer 运行于 Electron 主进程的独立服务模块，Chrome 作为子进程执行网页。第一版不额外引入后台服务器或数据库。
- 使用 `puppeteer-core` 与 `@puppeteer/browsers`，锁定匹配的浏览器 revision。构建阶段下载浏览器，运行阶段显式指定 `executablePath`。
- 主进程持有配置、浏览器、Cookie、文件系统和剪贴板权限；preload 只暴露经过定义的 IPC 接口；React 只展示画面与转发输入。
- 远端网站不加载进 Electron 的 WebContents，也不使用 webview/iframe 作为实际网站容器。
- 预定目录：
  - `src/main/browser/`：实例生命周期、标签管理、画面流、输入转发。
  - `src/main/storage/`：配置存储、Cookie 快照与加密。
  - `src/main/ipc/`：接口注册、调用方检查和参数校验。
  - `src/preload/`、`src/shared/`：受限桥接、公共类型和校验定义。
  - `src/renderer/src/features/workspace/`、`sites/`、`settings/`：三个业务模块。
  - `scripts/`、`tests/`：浏览器准备与打包校验、单元和集成测试。

## 网站配置与浏览器生命周期
- 网站配置包含 UUID、名称、初始 URL、排序、创建/更新时间、Cookie 快照元信息；浏览器目录由 UUID 推导，不使用名称或域名作为目录名。
- 页面管理提供新增、编辑、删除、启动、停止、查看状态、管理 Cookie 和清除登录数据。
- URL 限定为 HTTP/HTTPS，拒绝内嵌用户名密码；启动时打开配置 URL。修改运行中配置的初始 URL 不自动导航，界面提示下次启动生效。
- 每条配置启动一个 Chrome，使用独立 `userDataDir` 和默认持久化 BrowserContext；不使用重启即丢失存储的临时隐身 Context。
- 默认 headless 模式、`pipe: true`、固定 viewport `1280×800`、DPR 1；保留 Chrome sandbox，不开启公网调试端口。
- 状态为 stopped、starting、running、stopping、error；同配置操作串行化，启动名额在 starting 阶段即占用，避免重复启动和并发越界。
- 默认最多运行 4 条配置；启动和导航分别设置 30 秒超时。网站导航失败保留标签并展示重试入口，不拖垮其他实例。
- 应用启动不自动打开网站；停止配置保留浏览器目录和登录数据。删除配置及清除登录数据均需明确确认，并先停止对应浏览器。
- 单应用实例运行。关闭主窗口或退出时，如有浏览器运行则确认；确认后停止输入与画面流、保存快照、关闭 Chrome，再退出。超时仅清理本应用持有的子进程，不影响用户自己的 Chrome。
- Chrome 意外退出后释放并发名额、展示错误、允许重新启动，不无限自动重试；对 profile 占用和异常退出给出可恢复提示，不盲目删除锁文件。

## 主界面、网格和配置内标签
- 默认中文界面，左侧导航为“工作台 / 页面管理 / 项目配置”；采用简洁桌面工具布局。
- 网格卡片显示名称、当前 URL、状态、标签数量、最后画面和启动/停止/放大入口。网格不转发网页输入，避免误操作。
- 放大视图提供内部标签栏、地址栏、返回/前进/刷新、返回网格按钮和可交互画面；标签展示标题、加载及错误状态。
- 支持新建标签、切换和关闭标签；新窗口归入原配置并激活，保留 opener 关系以兼容登录回调。关闭当前标签后选相邻标签，关闭最后一个后保留空白标签。
- 首期每配置最多 8 个标签，超出时拒绝并提示；只对当前标签采集实时画面，其他标签保持网页会话运行，不强制冻结。
- 每次重新启动配置仅打开初始 URL，第一版不恢复上次标签列表。
- `about:blank` 仅作为内部空白页；网站请求的 file、自定义协议和外部应用启动默认拒绝并提示。普通 HTTP/HTTPS 导航在受控浏览器内完成。

## 实时画面与输入映射
- 优先通过 CDP `Page.startScreencast` 获取 JPEG 帧，首帧主动截图；接口异常或持续无法出帧时降级为无重叠的定时截图并显示降级状态。
- 默认网格目标 2 FPS、放大目标 15 FPS、JPEG quality 70；这些是刷新上限，不承诺固定帧率。截图降级模式最高 5 FPS。
- 每配置仅保留最新待发送帧，及时确认 CDP 帧；限制 IPC 未消费帧数，使用实例代次、标签 ID 和帧序号丢弃过期帧，避免切换后串画面或无界排队。
- 标签切换、页面关闭、停止实例时清理监听器和计时器；应用最小化或隐藏时暂停画面采集，但不停止网站。
- React 使用 Canvas 等比显示画面，依据实际内容区域和远端 viewport 换算坐标，排除留白区域；不因网格/放大切换改变网页 viewport。
- 放大模式支持点击、双击、拖动、滚轮、Tab、Enter、Backspace、方向键和常见编辑快捷键；输入命令只发往获得操作焦点的活动标签。
- 鼠标移动节流，按下/抬起保持顺序；用 pointer capture 完成跨边界拖动，失焦、换标签或离开操作视图时释放所有已按下按键和鼠标键。
- 中文通过本地输入代理承接 composition，再用 `Input.insertText` 等方式提交；避免组合输入和物理按键重复发送。
- 文本复制由用户操作触发，读取远端普通选区或非密码文本输入框选区后写入本机剪贴板；粘贴将本机纯文本送入远端焦点。覆盖常见输入框与 contenteditable，不承诺富文本、文件剪贴板或网站自定义复制协议。
- 普通网页 JS alert/confirm/prompt 使用应用内对话框承接；系统原生菜单、系统权限及音视频不在基础交互保证范围。

## 登录态与 Cookie 管理
- `userData/profiles/<siteId>/` 保存 Chrome profile，持续保留 Cookie、localStorage、IndexedDB 等网站数据；网站失效、主动登出、会话过期仍可能要求重新登录。
- `userData/config.json` 保存带 schemaVersion 的站点及全局配置；Cookie 快照和待应用修改存入独立加密文件，配置只记录引用和更新时间。
- 使用 Electron `safeStorage` 保护 Cookie 敏感数据；不可加密或解密失败时明确报错，不降级为明文。界面默认遮蔽 Cookie 值，仅在用户打开编辑器时读取明文。
- 自动每 30 秒、手动点击保存、停止及退出前采集 Cookie 快照。无差异则不重复写入；网站关闭时的失败不阻止清理进程，但必须提示保存失败。
- 浏览器 profile 是运行会话的主要来源；不在每次启动时用旧快照覆盖 profile。快照支持显式恢复；会话 Cookie 或其他失效凭据不保证跨重启有效。
- JSON、字符串、表格统一转换为同一 Cookie 模型。保留受支持的 domain、path、expires、httpOnly、secure、sameSite、分区等属性；无法无损支持的字段明确提示，不静默丢弃。
- Cookie 字符串按照第一个等号拆分每项，不做 URL 解码；默认作用域为配置 URL 的 host、path 为 `/`、secure 按 HTTPS 决定，并提示该格式不能还原完整属性。
- 导入默认合并，不清空无关 Cookie；识别键包含名称、域、路径和分区信息。表格支持明确删除条目，校验过期时间、域及安全属性，并展示逐项错误。
- 运行时应用修改直接更新对应 Context，成功后再持久化；停止状态保存加密的待应用修改，在下次导航前应用，成功后清除待应用标记。自动快照不得覆盖未应用的手动修改。
- 所有本地配置写入串行化并采用临时文件原子替换；配置保留上一份有效备份，损坏时提示恢复，不能静默清空。
- 安全边界明确：Cookie 快照加密不代表整个 Chrome profile 全盘加密；首期不提供明文登录态导出或跨设备迁移。

## 项目配置与 IPC 安全
- 全局设置包含：最大运行数（1～4，默认 4）、网格刷新上限（1～5，默认 2）、放大刷新上限（5～30，默认 15）、画质（40～90，默认 70）、导航超时（10～120 秒，默认 30 秒）。
- 提供数据目录只读展示及打开目录、应用与浏览器版本展示；变更即时应用。下调运行上限不强制终止现有实例，只阻止新增。
- IPC 按站点配置、运行控制、标签、输入、Cookie、设置分组；所有参数由共享 Zod schema 校验，校验发送方、实例归属、标签归属、状态及输入范围，返回统一错误结构。
- Electron 启用 contextIsolation、renderer sandbox、禁用 nodeIntegration，配置 CSP；禁止远端导航接管应用窗口，不暴露通用文件读写、任意脚本执行或任意 IPC 转发接口。
- 日志只记录必要的生命周期和错误，脱敏 URL 查询信息；不记录 Cookie 值、密码、键盘文本、剪贴板正文或网站画面。

## 浏览器分发与 macOS 打包
- 使用 electron-builder，将完整 Chrome bundle 放入 `extraResources`，位于 ASAR 外，保留必要文件、可执行权限及 bundle 结构。
- 开发态浏览器缓存位于项目内；打包态从 `process.resourcesPath` 查找。安装包不得依赖开发机上的 Puppeteer 全局缓存。
- 分别提供 arm64、x64 构建目标并嵌入对应架构浏览器，不制作混合浏览器的 universal 包；实际运行验证以可获得的硬件为准，不能将未测试架构标记为通过。
- 配套开发、类型检查、lint、测试、构建、浏览器准备及 macOS 打包脚本。浏览器缺失、架构不符或启动失败给出可诊断错误，不擅自改用本机 Chrome。
- 第一版交付当前机器架构的本地开发包和可复现打包配置；签名、公证配置预留环境变量入口。没有用户证书和授权时，不宣称已完成可对外分发的签名、公证。

## 实施顺序与验证
1. 先建立最小纵向链路：Electron 启动附带 Chrome → 独立 profile → 首帧/实时画面 → 坐标点击及中文输入 → 正常关闭。验证 CDP 不可用时的截图降级，以及打包后的浏览器路径。
2. 完成配置存储、并发限制、生命周期、Cookie 解析/编辑/加密与待应用修改。
3. 完成网格、放大操作、内部标签及登录弹窗流程，再接入全局设置和异常反馈。
4. 使用 Vitest 测试 URL/Cookie 校验、Cookie 合并与删除、配置读写/损坏恢复、坐标换算、状态机、并发名额、帧背压和清理。
5. 使用 Playwright Electron 与本地 HTTP 测试站集成验证：两个配置登录数据隔离、重启恢复持久化 Cookie/localStorage/IndexedDB、三种 Cookie 输入、弹窗回调、标签关闭、中文及复制粘贴、拖动/滚轮、异常退出重启、应用退出无残留受控进程。
6. 本地测试站模拟过期 Cookie、密码框、导航失败、JS 对话框、跨域 iframe 输入和持续动态图；第三方真实登录由用户人工验收，不自动填写账号或处理验证码。
7. 在当前机器同时运行 4 条配置，观察至少 10 分钟的刷新、交互、CPU/内存及待发送帧，确认无持续队列增长、卡死或跨配置串数据；性能指标报告实测，不预先承诺硬件无关数值。
8. 打包后脱离开发缓存启动验证，确认无需预装 Chrome，profile 和 Cookie 文件均存于用户数据目录。最终交付代码、脚本和已执行/未执行验证项说明。

## 验收边界与默认假设
- 产品名暂定 Octo Fetch；中文界面，启动手动开启网站，退出关闭所有受控浏览器。
- 所有业务数据保存在本机，不引入云端服务或账号系统；首次开发/构建需要网络下载依赖及浏览器，安装包运行时不再下载浏览器。
- 网站登录态只能尽力保存；Cookie 不一定能替代完整登录。Headless、人工输入和画面映射都不能保证淘宝等第三方网站接受该环境或通过风控。
- CDP screencast 属实验性接口，必须锁定匹配浏览器并验证降级；macOS 签名与公证、其他架构实机验证若缺少环境则明确列为未完成条件。
