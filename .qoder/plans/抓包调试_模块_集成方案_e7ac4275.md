# 抓包调试模块

## 已确认的范围与选型
- 抓取 Octo Fetch 内置浏览器，以及手动配置代理的外部浏览器、手机和应用；支持 HTTPS 明文查看。
- 采用 **Whistle + 现成工作台**，Octo Fetch 提供原生配置、生命周期、网站接入与自动化接口。
- 第一版包含用户选定的全部增强：网站一键接入、局域网接入、上游代理串联、脚本／MCP 调用。
- 调研对比：Whistle 为 Node.js／MIT，现成界面和规则功能最贴合；Mockttp 适合自建 React 界面，但需重做调试工作台；mitmproxy 需额外平台运行组件；Charles／Proxyman／Fiddler 更适合作为外部工具。
- 锁定已核对源码的 `whistle@2.10.10`，升级需重新执行适配层契约测试，不直接跟随浮动版本。
- 参考：[Whistle](https://github.com/avwo/whistle)、[Mockttp](https://github.com/httptoolkit/mockttp)、[mitmproxy](https://github.com/mitmproxy/mitmproxy)、[Whistle 调试规则](https://wproxy.org/docs/rules/enable.html)。

## 模块界面与默认配置
- 侧栏新增“抓包调试”，页面分为“工作台”“启动配置”“接入与证书”。原生区域沿用全局主题令牌、同行对齐和紧凑间距；Whistle 区域保留其界面，不重写 Network／Rules／Composer。
- 启动配置：代理端口默认 `8899`，整数 `1024–65535`；应用启动时自动启动默认关闭；HTTPS 解密默认开启；局域网访问默认关闭；外部客户端默认上游代理为空。
- 提供启动、停止、重启按钮，以及真实的 `stopped / starting / running / stopping / error` 状态、实际地址、错误原因与依赖网站数量。运行状态不作为配置持久化。
- 保存配置与启停分离；端口、监听范围等变更提示“重启代理生效”，不静默中断现有连接。占用端口明确报错，不偷偷更换用户配置的端口。
- 网站接入表支持勾选网站，显示“未接入／已生效／待重启”；修改保存后由用户显式重启网站，不自动重放页面导航。
- 接入页显示本机／局域网地址、客户端配置步骤、CA 指纹及导出入口；说明停止代理后外部客户端需手动撤销代理设置。

## 服务架构与引擎适配
- 新建 `src/shared/capture.ts`，集中定义配置、状态、查询、详情、控制命令及子进程请求／应答 Schema。
- 新建 `src/main/capture/`，包含 `service.ts`、`capture-process.ts`、`engine-adapter.ts`、`gateway.ts`、`upstream.ts`、`view.ts` 和证书／查询辅助模块。
- 使用一个独立 `utilityProcess` 承载 Whistle 与流量处理，主进程只管理配置、受信 IPC、窗口和生命周期。Whistle 会修改网络全局对象并注册异常处理器，禁止直接加载进 Electron 主进程。
- 通过 NPM 接口启动，不依赖全局 `w2`、用户安装的 Node.js 或 shell 常驻守护进程；不启动 cluster。
- 固定独立的数据目录 `userData/capture/`；引擎环境在首次加载前完成隔离，避免读取用户全局 `.whistle` 配置、插件和证书。禁用第三方插件发现、安装及自动更新入口。
- 显式启用 Whistle `safe` 模式，保持目标服务器和 HTTPS 上游代理的证书校验；不沿用其默认放宽校验行为。
- 将非稳定的引擎访问集中封装在 `engine-adapter.ts`：启动、状态、流量事件、详情查询、来源元数据、受控路由、证书和管理界面。业务层不得散布内部 CGI 路径或直接访问 Whistle 全局对象。
- 启动以代理和管理端均就绪为准；30 秒未就绪视为失败并回收资源。所有控制操作串行化，退出和异常路径拒绝未完成请求、关闭监听与连接，超时终止子进程；不无限自动重启。

## 流量入口与网站代理串联
- 链路固定为：`客户端 → 应用入口 → Whistle → 对应出口中继 → 原上游代理／目标站点`。
- 外部客户端使用配置的公共端口；每个接入网站分配仅回环监听的独立内部入口。网站身份由服务创建的入口与运行代次确定，不能依赖域名或客户端自报的网站 ID。
- 单引擎适配层负责将可信来源上下文贯穿 HTTP、CONNECT、HTTPS 解密、HTTP/2 和 WebSocket。入口清除客户端伪造的内部控制头；来源与路由元数据只用于本地处理，不发往目标网站。
- 为各网站建立独立出口中继；采用 `proxy-chain` 实现 HTTP／HTTPS／SOCKS5 上游连接，不自行重写认证和 SOCKS 协议。Whistle 规则仅引用本地中继，不含原代理账号密码。
- 原网站代理地址、绕过列表及 `proxyCredentialId` 保持不变；只覆盖浏览器本次启动使用的有效代理。原认证由出口中继处理，禁止把上游凭据交给抓包入口的 `page.authenticate`。
- 沿用原绕过列表及 Chromium 默认回环绕过语义；被绕过的请求不经过抓包，界面明确提示，不在第一版擅自扩大代理范围。
- 网站无原代理时直接出站；外部客户端独立使用模块配置的默认上游。沿用现有协议边界：HTTP／HTTPS Basic 认证、无认证 SOCKS5，不新增 NTLM 或 SOCKS 用户认证承诺。
- 原凭据继续由 `ProxyVault` 加密保存并保留运行快照引用；模块的外部上游凭据使用独立加密文件。日志、规则、流量详情、快照中不得泄露这些代理凭据。
- 检测上游指向本模块入口、管理端或出口中继的代理环路；出口不可达或认证失败时明确失败，禁止自动直连回退。
- 原始抓包记录的重放保留网站出口上下文；网站运行代次失效后拒绝沿用过期路由，提示重新选择来源。新建 Composer 请求默认走外部客户端出口。

## 与浏览器生命周期衔接
- `siteDraftSchema` 增加默认关闭的 `captureEnabled`；旧配置通过默认值兼容，局部保存网站时保留未提交字段。
- 修改 `src/main/browser/manager.ts` 和 `src/main/browser/options.ts`，在启动前获取抓包运行租约，生成有效代理、证书参数和出口快照；启动失败、停止及意外断开均释放租约。
- 将接入开关及有效抓包配置纳入运行配置比较；运行中的网站继续使用启动快照，修改后显示待重启，不改变其当前出口。
- 接入网站启动前要求代理已运行；未运行时返回可操作提示，不静默直连。桌面提供“启动代理”入口。
- 有网站租约时，停止／重启代理默认拒绝；桌面可经明确确认执行“先停止关联网站，再停止代理”，保留 Cookie 和登录目录。脚本／MCP 不自动停止关联网站。
- 代理意外退出时关闭其连接并告警，不将网站切换直连；恢复后提示用户重新加载或重启受影响网站。
- 应用正常退出按任务／脚本、浏览器、抓包服务的依赖顺序清理；启动失败路径也回收服务。

## HTTPS 与局域网安全
- 为本模块生成独立持久化 CA；目录权限 `0700`、私钥 `0600`。仅导出公开 CA 证书，展示 SHA-256 指纹和安装／移除说明；不自动修改系统钥匙串或系统代理。
- 内置 Chrome 仅在接入抓包时添加该 CA 公钥对应的 `--ignore-certificate-errors-spki-list`，以真机验证其限定范围；不为抓包自动开启全局 `acceptInsecureCerts` 或 `--ignore-certificate-errors`。
- CA 重置只允许在服务及关联网站停止后执行，并二次确认；提示所有外部客户端须重新安装证书，旧证书需手动移除。
- 开启局域网访问时必须配置允许的客户端 IP，默认空列表不放行；真实 socket 地址校验，不能信任 X-Forwarded-For。提供当前网卡地址，提示仅用于可信局域网，不开放公网。
- 公共入口只提供代理服务；阻断访问自身管理端、私有服务端口、内置管理域名及其解析到本机后的绕行方式，防止通过代理反向访问管理 API。
- Whistle 内部代理与管理端均仅监听回环地址，管理端使用每次启动生成的独立鉴权信息。局域网开关不能扩大管理端监听范围。
- 明确限制：证书固定、mTLS、未采用代理的应用可能无法解密；第一版不承诺通用 UDP／QUIC／HTTP3 抓包或绕过证书固定。受控 Chrome 接入时关闭 QUIC，使用 HTTP 代理链路。

## Whistle 工作台隔离与能力
- 使用 `WebContentsView` 嵌入，不放开主窗口 webview、不关闭主窗口 `webSecurity`，无需放宽主页面 CSP。
- 独立非持久化 session，无 preload、无 Node 集成、启用 sandbox／contextIsolation；无法访问 `window.octo`。
- 主进程只允许加载当前引擎管理 origin，鉴权仅注入该 origin；拒绝任意导航、弹窗和系统权限。页面切换、最小化、对话框及销毁同步控制视图可见性与边界。
- 复用并验收：HTTP／HTTPS 请求列表与筛选、Headers／Query／Body、JSON／文本查看、耗时与错误、WebSocket 帧、复制 cURL、Composer 编辑重放、HAR 导入导出、域名映射、请求／响应改写和 Mock、延迟／限速规则。
- 文件下载／HAR 导出走用户保存确认；导入通过显式选择文件。提示报文、Cookie、Authorization、请求正文可能包含敏感信息，原始导出不宣称已自动脱敏。
- 规则可访问本地资源，工作台属于本机用户的可信调试工具，不视为安全沙箱；不额外启用第三方脚本插件、Weinre 或 Console 注入。
- 与现有注入规则的顺序写入使用提示：页面请求注入在代理之前，代理响应改写在页面响应注入之前；被 CDP Mock、浏览器缓存或 Service Worker 直接满足的请求可能不经过代理。

## 流量查询与自动化接口
- 常规 `Snapshot` 只包含服务状态、计数、地址、配置待生效状态，不携带报文、证书私钥或管理鉴权信息。
- 查询直接读取引擎的有界缓存，不在主进程复制全部正文；配置 `reqCacheSize=1000`、`frameCacheSize=720`，尊重引擎的软淘汰语义，不承诺历史永久保留。
- 对外查询使用本次服务启动 generation 加记录 ID；支持来源网站／外部客户端、URL 子串、方法、状态码、时间范围和游标，每页默认 50、最多 100。详情按需返回，请求和响应正文各最多 1 MiB，保留重复 Header、编码和截断标记。
- 已淘汰、清空或旧 generation 的记录返回明确不可用错误，不把缺失正文伪装为空正文。报文默认不持久化；规则与配置保留，HAR 等仅由用户显式导出。
- 新建 `src/main/mcp/capture.ts`：`capture_status` 为 read；`capture_requests`、`capture_detail`、`capture_start`、`capture_stop` 为 full。完整 URL、Header 和 Body 都按敏感数据处理，不因“查询”就授予低等级令牌。
- 模块提供默认关闭的“允许 MCP 访问抓包”开关，仅桌面可开启；关闭后拒绝抓包数据／控制调用，状态仅返回非敏感信息。不提供修改系统代理、安装证书、任意规则执行的 MCP 工具。
- 三类可信脚本统一提供 Promise API：`octo.capture.status()`、`query(filter)`、`get(id)`、`start()`、`stop()`；启动和停止仅作用服务运行态，不修改自动启动、LAN、CA、上游配置。
- 模块的脚本访问总开关默认关闭；每个脚本另设本机授权 `none / read / control`。授权不随脚本导出／导入或复制传播；新脚本默认 none。行动／注入只读本运行网站，沙箱可读全部来源但授权时明确提示；start／stop 另要求 control。
- 通过宿主上下文确定来源，不能接受脚本伪造的 siteId 扩大查询范围。沿用现有数据客户端模式，扩展 action Worker、injection Worker、sandbox MessagePort 的双向协议，统一请求 ID、15 秒超时、每脚本每分钟 120 次限流和停止时拒绝在途请求。
- 同步脚本编辑器类型提示、脚本编写契约和 MCP 指南；这些权限是宿主 API 访问约束，不宣称能沙箱隔离本就可信的 Node 脚本。

## 实施顺序与验收
1. 先完成锁版本的引擎适配验证：真实 Electron 子进程启动、隔离工作台、严格 HTTPS 校验、限定 CA 信任、HTTP／CONNECT／HTTPS／WebSocket 来源传递，以及两个网站访问同域名但使用不同出口。任一核心能力不成立即报告具体阻塞，不静默改成共享出口或全局忽略证书。
2. 实现配置、生命周期、入口／出口、证书及浏览器租约，再完成原生模块页面与 Whistle 嵌入。
3. 实现有界查询、脚本授权和三种脚本通道、MCP 工具，最后完成平台打包验收。

### 自动化与真机检查
- 单测：旧配置迁移、端口／IP 校验、状态机并发、租约释放、代理环路、无直连回退、generation／游标、截断和权限矩阵。
- 本地网络集成：HTTP／HTTPS／HTTP2、压缩／二进制／流式响应、重定向、重复 Set-Cookie、WebSocket；严格拒绝不可信目标证书和 HTTPS 上游证书。
- 代理串联：两网站同域名分别通过不同出口，认证 HTTP／HTTPS 和无认证 SOCKS5；原绕过规则、认证失败、凭据轮换及运行快照；目标服务器收不到内部头或代理密码。
- 安全：LAN IP 未授权拒绝、管理域名／IP／CONNECT 绕行拒绝、伪造来源头无效、工作台不能调用主应用 IPC；低等级 MCP、未授权脚本和跨网站读取均拒绝。
- E2E：启停、端口占用、配置待生效、网站接入／退出、证书导出、HAR 导入导出、改写／重放、视图切换、子进程崩溃及退出无残留监听。
- 执行 `npm run typecheck`、`npm run lint`、`npm test`、新增及现有浏览器／注入／脚本／MCP 回归；最后验证 arm64／x64 打包产物中的引擎、静态界面、HTTPS 和出口链路。不可用架构或手机实机测试单独列为未验证，不以 mock 结果代替。

## 第一版边界
- 不自动配置系统代理或安装系统证书，不提供 VPN／透明网关模式，不接入公共云流量服务。
- 不自建第二套抓包工作台，不做长期抓包数据库、自动抓包上传、任意插件市场、脚本／MCP 规则编辑或批量重放。
- 原生模块负责安全接入与自动化查询；Whistle 的调试操作由用户在隔离工作台显式执行。
