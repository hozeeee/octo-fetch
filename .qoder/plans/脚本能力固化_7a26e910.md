# 脚本能力固化

## 概要
新增一条完整纵向链路：`shared` 契约 → `ScriptStore`/`ScriptLogStore` 落盘 → `ScriptRunner`（node:vm 沙箱）→ IPC/preload → 侧边栏「脚本能力」模块 → MCP 脚本工具与引导。

已确认的四项决策：
1. 执行环境：主进程 `node:vm` 独立上下文，注入 `page`/`browser`/`octo`，无 `require`/`process`/`fs`。
2. 站点匹配：严格域名模式匹配，不提供强制运行入口。
3. MCP 分级：读类工具一级；写与运行均为三级。
4. 变量为声明式 schema；执行日志落盘并按脚本轮转。

## 共享契约（src/shared/scripts.ts 新建、model.ts 扩展）
- `scripts.ts`：域名模式正则与 `matchesUrl`（`*.taobao.com` 同时匹配 apex 与子域，`taobao.com` 仅精确匹配）；`coerceVariables` 做必填/类型/枚举/区间校验；`SCRIPT_CONTRACT` 编写契约文本（UI 与 MCP 共用同一份）；`SCRIPT_TEMPLATE` 手动新建模板。
- `model.ts`：`scriptVariableSchema`（key/label/kind=text|number|boolean|enum/required/default/options/min/max）、`scriptDraftSchema`（name/description/match/variables/timeout/source）、`scriptSchema`（+id/origin/createdAt/updatedAt/values/统计）、`scriptRunSchema` 与 `scriptLogSchema`。
- 快照只带 `ScriptSummary`（不含 source 与日志），避免 40ms 级状态推送携带数万字符源码；source 与运行记录走独立 IPC 通道按需拉取。
- 命令新增 `script.save` / `script.delete` / `script.run` / `script.cancel` / `script.logs.clear`；`DesktopAPI` 增加 `script(id)` 与 `scriptRuns(id)`。

## 主进程
- `src/main/scripts/store.ts`：`ScriptStore` 管理 `userData/scripts.json`（原子写 + `.bak` 备份 + SerialQueue，沿用 ConfigStore 既有模式）；`ScriptLogStore` 管理 `userData/script-logs/<scriptId>.json`，按脚本保留最近 N 次运行并淘汰超限记录。
- `src/main/scripts/runner.ts`：`ScriptRunner`。把源码包进 `(async function octoScript(){ ... })()` 后 `vm.runInContext`；注入 `page`、`browser`、`octo`（`site`/`vars`/`log`/`sleep`/`output`/`signal`）与受管的 `console`、`setTimeout`。超时与取消通过 `AbortSignal` + `Promise.race`，同时把 `page.setDefaultTimeout` 压到剩余预算，结束后恢复。返回值必须可 JSON 序列化。同一站点只允许一个运行中的脚本。
- `BrowserManager` 增加 `scriptSession(siteId, tabId?)`：先 `agentFocus` 让画面跟随脚本，再取回 `browser`/`page`；**不占用实例队列**，否则数分钟的脚本会阻塞 30 秒一次的 Cookie 自动快照。
- `ipc/register.ts`、`preload/index.ts`、`main/index.ts`：注册新命令与两个只读通道；`script.delete` 沿用 `dialog.showMessageBox` 二次确认。

## MCP（src/main/mcp/tools.ts、server.ts）
- 一级：`script_guide`（返回编写契约，让 agent 拿到准确的注入 API）、`list_scripts`、`read_script`、`read_script_runs`。
- 三级：`save_script`（origin=agent）、`run_script`、`delete_script`。
- 引导 agent 走固化方向：改写 `INSTRUCTIONS` 明确「重复流程先 `script_guide` + `list_scripts`，优先复用或固化脚本」；在 `click`/`type_text`/`press_key`/`scroll` 的描述末尾追加固化提示。

## 渲染层
- 侧边栏新增「脚本能力」（`CodeOutlined`，带数量角标），`store.ts` 的 `View` 联合类型同步扩展。
- `features/scripts/Scripts.tsx`：页面头部 + 编写说明面板 + 脚本表格（名称/来源/适用站点/变量/运行统计/操作）。
- `features/scripts/ScriptEditor.tsx`：名称、描述、域名模式（tags）、超时、变量列表（Form.List）、源码文本域。
- `features/scripts/ScriptRun.tsx`：运行弹窗（仅列出域名匹配且运行中的站点、按 schema 渲染变量表单、运行中轮询日志与结果）与历史日志弹窗。
- `styles.css` 补充脚本模块所需类名，沿用现有配色与圆角规范。

## 测试
- 更新 `tests/unit/core.test.ts` 中两处会被新工具打破的断言：一级工具清单、以及 `/token|mcp|execute|eval|script/` 黑名单（收紧为仍禁止 `token`/`mcp`/`execute`/`eval` 类工具名，脚本工具改为显式白名单校验）。
- 新增用例：域名模式匹配（apex/子域/不匹配）、变量校验（必填缺失、枚举越界、数字区间、类型转换）、沙箱（无 `require`/`process`、超时中止、`console` 归集为日志、返回值不可序列化时报错）、日志轮转淘汰。
- 验证命令：`npm run typecheck`、`npm run lint`、`npm run test`。

## 前提与边界
- vm 沙箱是能力裁剪而非强安全边界：脚本由本机用户或其授权的三级 agent 提供，等价于信任本机脚本；此点在 UI 说明与 MCP 契约中明示。
- 超时/取消后不再等待脚本，已发起的浏览器调用可能继续完成，运行记录标记为 timeout/cancelled。
- `scripts.json` 为明文（不含凭据）；Cookie 与令牌仍走原有加密通道。
